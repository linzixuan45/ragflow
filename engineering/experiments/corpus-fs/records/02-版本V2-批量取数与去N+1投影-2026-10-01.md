# 版本 V2 — 批量子树取数 + 删除 N+1 投影（2026-10-01）

> 目标：把「每次请求全量重建目录投影」的取数成本降下来，并**证明语义不变**。
> 上一版：[`01-版本V1-同步段移出事件循环-2026-10-01.md`](01-版本V1-同步段移出事件循环-2026-10-01.md)
> 协议与硬性规则：[`README.md`](README.md) §0

---

## 1. 假设与改动

- **假设**：V0 每库 `search_context` 的 15~53 条 SQL 来自 `_descendant_files` 的「每个目录一次查询」（N+1）与 `_dataset_file_root` 的「每个 link 一次 `get_by_id`」，以及 `_documents()` 被重复调用 3 次。改成「按目录层级批量取数 + 内存建树 + 文档/链接一次取」应当降低 SQL 与耗时，且**投影结果逐字段不变**。
- **改动**（`api/apps/services/corpus_fs_service.py`，+63/−41）：

| 位置 | 改动摘要 |
|---|---|
| `_dataset_file_root` | 由「每个 link `FileService.get_by_id` 爬」改为「按 link 顺序逐层 `File.id.in_([id])` PK 查询」，语义不变（第一个命中即返回） |
| 新增 `_files_by_ids` / `_files_by_parents` | 批量取数原语（按 id 集合 / 按父目录集合，排除自环） |
| `_descendant_files` | 由「每目录一次 `list_all_files_by_parent_id`」改为「**每层一次** `parent_id IN (...)`」，N+1 → O(深度) |
| 新增 `_dataset_tree` / `_file_documents` | 统一取数入口与「文件→可见文档（含 `active_document_id`）」解析；`_projection` 与检索共用一份实现 |
| `_projection` | 改为使用上述入口；links 只查一次（原先 `_dataset_file_root` 与 `_projection` 各查一次） |

- **预期**：单库 `search_context` SQL 15→≤12、嵌套目录库 53→≤16；`tree/find/stat/usage/content` 的固定成本（V0 ~0.25s）下降；L(N) 小幅改善；M2 不回归。
- **一并试验但被否决的改动（R8 负结果）**：曾实现「惰性 scope 索引 `_CorpusScopeIndex`」（只算可见文档 id，路径按需解析）。实测在同一进程内与重构后的 `_projection` 等价（fa5c87b8：0.146s vs 0.151s，物化全部条目仅 +0.011s），**没有收益**，且引入 ~120 行复杂状态 → **已删除**（代码里不留双路径）。

## 5. 结论与对比

- **本版结论：采纳。** 语义等价经逐字段证明（8 库 + 子目录 ALL EQUAL），单库列举接口 -35%~-70%，单库语义检索 -19%，多库 SQL -8%，邻扰 max -37%。
- **性能目标达成情况**：
  - 单库接口固定成本目标（原 0.25s 量级）→ **已达成**（0.15~0.25s）。
  - 多库 L(12) 目标（≤3s）→ **未达成**（13.14s，与 V1 持平），原因明确：成本已转移到「N 次召回 + N 次重排」，由 V3 解决。
  - M2（<0.10s）/ M3（<1s）→ 仍未达成，遗留 L1/L2 继续跟踪（L2 已从 4.10s 降到 2.60s）。
- **负结果记录（R8）**：惰性 scope 索引试验无收益，已删除；删除后代码只保留「批量取数 + 内存建树」这一条路径。
- 与预期差异：小库数（1~2 库）收益远超预期（-76% / -53%），因为单库请求的取数成本占比高；16 库的中位数受重排服务波动影响（19.41s 但逐次 15.26~20.38s）。

## 7. 风险与后续

- **残余风险**：
  1. **bind mount 的 inode 陷阱（本版实际踩到）**：用原子写（编辑器/工具）修改 bind-mount 的单文件后，容器里仍是旧副本（实测容器内 md5 仍是 V0），必须 `--force-recreate`。已在 `重要信息.md` 记录过同类问题，本版再次验证。**教训**：改完代码先比 md5，再测。
  2. 少数单次测量出现离群值（c4bae8f6 的 `_projection` 0.451s、16 库 15.26~20.38s），说明该实例存在秒级抖动；判定一律以中位数为准，离群值不改结论。
  3. `_documents()` 仍是「整库全量文档行」，每库 1~2 次。大库（数万文档）下仍是 O(文档数) 成本；V3 之后可考虑按需取列。
- **未验证项（明确未测量）**：写路径（upload/move/delete/replace）未做端到端回归，仅由聚焦单测覆盖。
- **遗留项**：L1（M2 0.16s）、L2（M3 2.60s）。
- **下一步**：V3 —— 融合严格召回 + 逐库兜底 + 单次全局重排（目标 L(12) ≤3s），届时复测 L1/L2 并做质量门禁。
