# 试验 — 质量门禁与可复现性上界（2026-10-01）

> 性质：**不改代码的验证**（README §1：记为 `VX-试验`，不占用优化编号）。
> 目的：为 V3 之后所有**涉及排序**的改动建立准入判据。原有计划把"质量门禁"列为 B5，但 V3.2 实测发现：**同一份未改动代码重跑，top-10 自身就会变**，因此门禁必须先量化这个上界，否则无法区分噪声与回归。
> 关联：[`05-版本V3.2-词项相似度键集化-2026-10-01.md`](05-版本V3.2-词项相似度键集化-2026-10-01.md) §7、[`../后续实验计划-修订版-2026-10-01.md`](../后续实验计划-修订版-2026-10-01.md) §3-B5

---

## 1. 方法

新增 `../scripts/baseline/quality_gate.py`（两种模式）：

| 模式 | 作用 |
|---|---|
| `run` | 固定 10 条 query × 12 库，同一进程内重复 `R` 次；记录每次的 `wall`、top-10 的 `scope:path` 序列、分数、`raw/deduplicated/total`；计算**同版本自比**的 top-10 重合度（floor） |
| `compare` | 读入两次 `run` 的输出，逐 query 比较候选与基线的 top-10 重合度，并**以基线的 floor_min 为判据**给出 `PASS / UNDECIDED / REGRESSION` |

判据（无标注集，沿用 README §4.3 的代偿证据条款，并补上可复现性上界）：

```
overlap >= floor_min              -> PASS
floor_min - 1 <= overlap < floor_min -> UNDECIDED
overlap < floor_min - 1           -> REGRESSION   （任一 query 回归即整体不通过）
```

query 集（固定，写死在脚本里）：什么是人工智能 / 产品路线图和技术规划 / 投标文件的评分办法 / 团队本周的工作总结 / 深度学习模型的训练方法 / 知识库的权限怎么配置 / 报销流程是什么 / 部署方案与优化 / 语音助手 / zzzqqq 完全不相关的词（负对照）。

## 2. 结果

### 2.1 可复现性上界（floor）

| 会话 | label | 重复 | floor（每 query 均值的平均） | 最差单 query 的 floor_min |
|---|---|---|---|---|
| 1 | V3.3 | 3 | **8.46 / 10** | **7 / 10** |
| 2 | V3.3b | 3 | **8.56 / 10** | **7 / 10** |

→ **同一份代码、同一进程内连续三次，top-10 平均就会丢 1.5 条**；最差的一条 query 丢 3 条。原因是重排服务的抖动与近分数并列（V3.2 §7 已记录）。

### 2.2 门禁校准：空跑（同一份代码，不同会话）

```
compare(V3.3, V3.3b):  pass=10  undecided=0  regression=0  -> PASS
```

→ 门禁**不产生假回归**。注意两次比较用的都是各自会话的第 1 次运行：同一位置的运行（例如都取第 1 次）之间差异明显小于会话内相邻运行之间的差异，说明抖动主要来自"连续调用"而非"跨会话"（重排服务预热/批处理效应）。**因此对照必须同位置配对。**

### 2.3 门禁校准：敏感度（真实改变排序的配置）

把 `vector_similarity_weight` 从 0.3 改为 0.9 作为候选：

| query | overlap | floor_min | 判定 |
|---|---|---|---|
| 什么是人工智能 | 5 | 7 | REGRESSION |
| 产品路线图和技术规划 | 3 | 10 | REGRESSION |
| 投标文件的评分办法 | 5 | 8 | REGRESSION |
| 团队本周的工作总结 | 0 | 9 | REGRESSION |
| 深度学习模型的训练方法 | 5 | 8 | REGRESSION |
| 知识库的权限怎么配置 | 4 | 9 | REGRESSION |
| 报销流程是什么 | 8 | 8 | PASS |
| 部署方案与优化 | 0 | 8 | REGRESSION |
| 语音助手 | 1 | 7 | REGRESSION |
| zzzqqq 完全不相关的词 | 10 | 9 | PASS |

```
summary: pass=2  undecided=0  regression=8  -> REGRESSION
```

→ 门禁**能抓住真实的排序改动**（不是恒 PASS 的橡皮图章）。

### 2.4 对已否决方案的追溯判定

V3.2 §7 的截断方案在 A/B 中 overlap 只有 **3~5 / 10**，而对应 query 的 floor_min 为 7~10 → 门禁会判定 **REGRESSION**。即：**该方案在门禁下无法通过**，与当时的定性结论一致。

---

## 3. 结论

1. **可复现性上界已经量化**：`floor` 平均 8.5/10，最差 query 7/10；任何"top-10 变了"的说法都必须相对它来读（V3.2 之前的所有跨版本排序讨论都缺这一项）。
2. **门禁可用**：空跑 10/10 PASS，敏感度 8/10 REGRESSION，且能追溯否决已知的坏方案。
3. **对照协议修正**（写回计划 §2.2）：跨版本比较必须
   - 同位置配对（都取第 1 次，或都取第 R 次），不要用"候选第 1 次 vs 基线第 3 次"；
   - 每 query 单独判，取最差者作为整体结论；
   - 会话内重复次数 R≥3，并报告 floor。

## 5. 局限与后续

- **没有标注集**：本门禁只能回答"排序是否被改动"，不能回答"是否更好"。真正的 Hit@10/MRR 仍需 20 条带标注 query；本试验为它留下了可复用的采集与对比框架。
- **判据只取 top-10 的路径集合**：不比较顺序与分数。若后续需要 MRR 类指标，`run` 输出里已保存 `rank` 与 `score`，可直接扩展。
- **负对照 query**（`zzzqqq 完全不相关的词`）目前同样返回 10 条（任意 chunk 兜底），说明 V0 的"文本不匹配库"质量问题仍在（计划 §3-F2 独立立项）。
