# 版本 V3.1 — 融合召回的覆盖判定改为按 scope 的可见命中（2026-10-01）

> 目标：修掉 V3 引入的可用性回归——严格窗口有命中、但命中全部落在请求 path 之外的知识库，**既不恢复也不兜底，该 scope 直接零候选**。
> 上一版：[`03-版本V3-融合召回与单次重排-2026-10-01.md`](03-版本V3-融合召回与单次重排-2026-10-01.md)
> 方案依据：[`../后续实验计划-修订版-2026-10-01.md`](../后续实验计划-修订版-2026-10-01.md) §3-B（B1/B2/B3）
> 协议与硬性规则：[`README.md`](README.md) §0

---

## 1. 假设与改动

- **假设**：V3 用「严格窗口的原始命中数（按 kb_id 聚合）」决定某库是否需要逐库恢复窗口。但严格窗口不做可见性过滤（一个窗口服务所有 scope），因此命中可能全部来自请求 path 之外的文档。这些命中会被 `_scope_of` 在重排前丢弃，却已经让该 scope 被判定为"已覆盖"。
- **改动**：

| 文件 | 改动摘要 | 规模 |
|---|---|---|
| `api/apps/services/corpus_recall_service.py` | `per_dataset`（按 kb_id、按原始命中）→ `per_scope`（按 scope、只计可见命中）；严格 / 恢复 / 兜底三个阶段统一用 `count_visible()` 记账；恢复与兜底按 scope 配对 zip，避免 k 库多 scope 时计数串台 | +45 / −25 行 |
| `test/unit_test/api/apps/services/test_corpus_recall_service.py`（新增） | 6 个用例：不可见命中触发恢复、可见命中不触发、恢复后仍空才兜底、同库两 scope 独立计数、嵌套 path 绑定首个可见 scope、失效文档不进候选池 | +190 行 |

- **先红后绿（B1 要求）**：把 `count_visible()` 临时替换回「按 kb_id 计原始命中」后，`test_scope_whose_strict_hits_are_invisible_gets_its_own_window` 与 `test_two_scopes_of_one_dataset_are_counted_independently` **失败**（`assert 0 == 1`：没有发出恢复窗口）；恢复修复后 6/6 通过。

- **预期**：受影响 scope 的候选从 0 恢复；`L(N)` 不回归（多出来的恢复窗口数量有限）；M2 不变。

## 2. 影响面

### 2.1 接口 / 契约

| 项 | 结论 |
|---|---|
| HTTP 路径 / 字段 | 无变化 |
| 响应字段 | 结构不变；`search_meta.raw_candidate_count` 对"此前被饿死的 scope"会**变大**（预期修复效果） |
| 排序 | 不发生改变：新增的候选来自原有恢复/兜底语义（V0 等价），不是新的召回通道 |
| 同库多 scope | `_scope_of` 仍绑定**列表首个**可见 scope；该行为由用例 `test_nested_scopes_bind_a_chunk_to_the_first_visible_scope_once` 固化为契约（V2 之前每 scope 各出一条，属有意收敛，记录在案） |

### 2.2 数据与检索质量

| 项 | 结论 |
|---|---|
| 子目录 scope | **修复**：`/Deerflow更新-加入原仓库改动`（6/221 可见）此前 0 候选，现在 10 条候选并进入结果 |
| 失效文档 | 未变更语义：文档不在 `visible` 集合时在重排前被丢弃（等价于 `_prune_deleted_chunks`；V3 融合路径不经过 `Dealer.retrieval`） |
| 兜底语义 | 保留：恢复后仍无可见命中的 scope 才走 `question=""` 的纯过滤窗口 |

## 5. 结论与对比

- **本版结论：采纳。** 修复了一个可用性回归（V0 存在、V3 丢失的能力），`L(N)` 无实质变化，功能守卫 95 passed（12 个 corpus 文件 + 新增 6 个 recall 用例 + 8 个 token-similarity 用例）。
- 与预期差异：`L(12)` 走高 5.5%，但低于当次噪声上界（MDD 15%，V3 噪声地板 cv 0.04），不构成回归。
- 遗留：§2.1 的"同库多 scope 绑定首个可见 scope"是**有意收敛**，需要在契约文档里写明；本次以用例固化。

## 7. 风险与后续

- **残余风险**：`raw_candidate_count` 上升会让重排池变大，极端库数（16/50 库）下与"池预算"相互放大——由 V4 的每库配额约束。
- **未验证项**：写路径未回归；DeerFlow 端到端未复测。
- **下一步**：README §4.2 的契约回归 pytest 化（B4）；质量门禁（B5）——本次实测发现**同一版本重跑的 top-10 自身重合度只有 8.6/10**，门禁必须先量化这个可复现性上界。
