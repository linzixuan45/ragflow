# 版本 V1 — 同步段移出事件循环（2026-10-01）

> 目标：消除「多库检索冻结整个 API 服务」的问题。**纯调度改动，检索结果不因本版本改变。**
> 上一版：[`00-版本V0-基线-2026-10-01.md`](00-版本V0-基线-2026-10-01.md)
> 协议与硬性规则：[`README.md`](README.md) §0

## 1. 假设与改动

- **假设**：V0 实测的 7.77s 事件循环冻结来自 `Dealer.retrieval` 内**同步**调用的重排（`rerank_by_model` / `rerank` / `rerank_with_knn`）与 `dataset_api_service.search` 内同步调用的 `retrieval_by_children`。把这些调用提交到既有的 `common.misc_utils.thread_pool_exec`（128 worker 专用池，已用于 `get_vector`/`dataStore.search`）后，事件循环在等待期间可继续调度其他请求。
- **改动**：

| 文件:行 | 改动摘要 | 规模 |
|---|---|---|
| `rag/nlp/search.py:616` | `self.rerank_by_model(...)` → `await thread_pool_exec(self.rerank_by_model, ...)` | 1 行改多行 |
| `rag/nlp/search.py:634` | OceanBase 分支 `self.rerank(...)` → `await thread_pool_exec(...)` | 同上 |
| `rag/nlp/search.py:647` | ES 分支 `self.rerank_with_knn(...)` → `await thread_pool_exec(...)` | 同上 |
| `api/apps/services/dataset_api_service.py:1105,1498` | `settings.retriever.retrieval_by_children(...)` → `await thread_pool_exec(...)` | 各 1 行 |

- **预期**：M2 `max_stall` 7.77s → **< 0.10s**；M3 邻扰 max 12.713s → < 1s；M1（L(N)）与 M5（单库接口）**不回归**（同一份计算，只是换了线程）；M8 单测仍 ≥ 80 passed。

## 5. 结论与对比

- **本版结论：采纳（带遗留项）**——事件循环冻结从"请求级灾难"降到"可忽略"，收益明确且零语义风险，保留。
- **但按协议 R1 不能标"完全达成"**：M2 目标 `<0.10s` 实测 **0.16s**，M3 目标 `<1s` 实测 4.10s。两项均列为遗留项，由后续版本关闭：
  - 遗留项 L1（M2 0.16s）：5 次 >50ms 停顿未被现有埋点覆盖。候选来源：`dataset_api_service.search` 内每库的同步 DB 校验/模型 bundle 构造（12 库 × ~6 次同步调用）、`CorpusToolService` 收尾阶段的 CPU（`citation_target` 位置重叠计算、HMAC、去重）。**V3 的召回服务重构会把这些从"每库一次"降为"一次/命中才做"**，届时复查。
  - 遗留项 L2（M3 4.10s）：邻扰的尾部来自**被拖慢的其他接口自身**（`tree` 要跑全量投影：221 文档的库 53 条 SQL + 全量文档行，在 DB 竞争下可达数秒），而非事件循环冻结。**V2 删除该 N+1 投影后复查**。
- 与预期差异：L(N) 的改善超出预期（预计持平，实测 12 库 -27%）——原因是同一请求内 N 个 scope 的重排现在可以重叠；副作用是重排服务会同时收到多个请求（实测其 6 路并发 0.61s，优于串行 0.93s，故为正向）。

## 7. 风险与后续

- **残余风险**：
  1. 重排从串行变为并行后，共享 rerank 服务的瞬时并发从 1 升到 N（12 库场景实测其并发能力 6 路 0.61s，仍优；但若其他租户同时在用，排队时间会互相影响，V5 的预算/限流应覆盖）；
  2. 事件循环不再冻结，但 `asyncio.to_thread` 仍与 Quart 同步路由共用默认执行器（20 worker）——本版把重排挪到了 128-worker 专用池，未触碰默认执行器的分配，V3 召回服务重构时统一收敛。
- **未验证项（明确未测量）**：单库 `/fs/search` 之外的检索入口（Dify/chat/dialog）未复测；本版改动对它们同样生效（同一 `Dealer.retrieval`）。
- **遗留项**：L1（M2 0.16s）、L2（M3 4.10s），归属 V2/V3 复查。
- **下一步**：V2（批量子树取数 + 内存树，删除 N+1 投影），并在 V2 复测 M3。
